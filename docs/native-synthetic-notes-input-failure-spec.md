# synthetic-foreground-notes-input: failure specification

This specification precedes a candidate implementation. This phase only reads saved safe diagnostics and local Xcode SDK headers, and tests the pure native policy entry. No Apple process, authentication, UI, foreground or input events are accessed by this agent. Default background commands remain event-free and focus-free. This is not a customer write permission or a statement that Apple notes can be submitted.

Recorded boundary: the saved actual compiled `item probe-notes` result `outputs/apw-apple-notes-probe-live-20261012.json` has two stable complete NotesField frames: AXTextField, no children, SelectedText/Range settable false with raw code 0, AXValue settable true, app-internal focus AXWindow. SDK says SelectedText readonly and notes frameworks may ignore CGEvent Unicode strings. AXValue/AXConfirm have already failed persisted Binding acceptance; those successes are not submission evidence.

1. No explicit foreground input request, synthetic_only missing, non-fixture expected state, real account/domain, nonempty credential, unexpected editable data, or an incomplete canonical preimage refuses before a focus or input attempt. Only exact titles `apw API 测试 · SSO 与备注` or `apw API 测试 · 独立备注`, original `APW_EXCHANGE_SYNTHETIC_V1` marker, empty password and `.invalid` identities/sites; no new records. The independent native op is `synthetic-foreground-notes-input`, with strict JSON Boolean `synthetic_only:true` and `foreground_focus:true`, complete expected/key and notes arguments. New notes must preserve original UTF-16 units literally as a prefix, append a nonempty bounded suffix containing `APW_FOREGROUND_INPUT_SYNTHETIC_V1`, contain no NUL, and fit 4096 UTF-16 units.
2. The original and current NSWorkspace foreground PID must already be the verified signed Apple Passwords PID. A known foreign global keyboard PID refuses. Nil global keyboard focus needs positive app-internal same-PID focus proof. The unique original standard window, editor, exact NotesField and its bounded ancestor chain must be independently complete and stable; no activation, raise, new window, mouse click fallback or authentication bypass.
3. This request's own editor must have two complete canonical frames equal the expected whole state, including sites/sharing/OTP/passkey/extra fields; raw fields must also agree. Existing user editors, duplicates or an incomplete full exact query/index proof, unmodeled editable verification seeds, stale nodes or owner changes hold.
4. First run the existing explicit foreground focus-only primitive. A setter error, unsupported focus attribute, app-internal focus remaining AXWindow, wrong or unknown field, foreign PID, incomplete ancestry or changed original state prevents all input. A successful setter alone is insufficient.
5. Event-posting access must already be granted by a read-only preflight. Do not call CGRequestPostEventAccess, change permissions, sign in, or prompt automatically. No held physical modifiers; failed/unknown modifier observation holds. Revalidate the signed target process and unchanged original foreground immediately before each attempted event.
6. Only CGEventPostToPid(verifiedPID, event) is a candidate. Never use global CGEventPost, System Events keystroke, clipboard/pasteboard, screenshots, keyboard layout changes, event taps, public channels, arbitrary process IDs or generic customer event APIs. Posting has no success return; queued delivery or a local AXValue change cannot prove a result.
7. The smallest candidate is one PID-addressed Command-A key pair, then independently prove the exact full UTF-16 selection of the original NotesField with unchanged whole preimage. If selection read is unsupported/incomplete/wrong, stop before text input. Merely advertising SelectedTextRange is not proof. No arrow/Home/End or mouse fallback. At most one selection pair; never resend on timeout.
8. One PID-addressed Unicode key pair replaces that selection with the exact original complete synthetic body plus a bounded test marker. No arbitrary extra text, truncation, replacement of original content, command flags on Unicode text, or per-character unbounded loop. UTF-16/multiline/CJK/combining/surrogate handling needs a self-owned fixture proof. The SDK explicitly permits a framework to ignore Unicode text, so this is an experiment, not an API contract.
9. Before Save, independently confirm the note equals exactly the planned postimage and all other canonical and raw fields remain original in two complete frames. Any unexpected typed result, different focus, user input, site/credential/sharing/OTP/passkey change or incomplete state holds without Save or speculative rollback.
10. Save only via the existing unique exact owned semantic Save/Done action, one attempt. Confirm a complete return to the list, then reopen the exact same fixture through the existing readKey exact query/complete-index path (never the diagnostic current-cohort shortcut) and compare the entire persisted state to the planned postimage. No response, editor disappearance, action success or local text change is sufficient. Lost replies are uncertain, never retry permission.
11. Errors after any attempted input preserve observed ownership and review status. After any attempted input, do not cancel, save, retry, or restore on an error: retain the editor and explicit review status. Before input, Cancel requires two fresh full original state comparisons and raw fields; cached metadata is insufficient. Unknown/partially edited states cannot be canceled or auto-restored. Recovery must not clear provenance and pretend success.
12. Reports contain only stage names, bounded attempt counts, safe raw codes, permission/focus/owner/selection/equality booleans and fixed flags; never original/replacement text, credentials, usernames, websites, key payloads or clipboard data. Successful synthetic persistence must still report customer_mutations:0 and must not expand default notes-set permissions.
13. Prior to actual Apple input, compile/test a self-owned fixture through its own real entry point to prove text-input model updates and save/readback; do not steal the user's foreground to run it. Root owns scheduling and any real Apple acceptance. If the focus-only or exact-selection prerequisite cannot be met, report the single failed gate and stop this candidate rather than adding fallbacks.

## Authorized self-owned fixture subtest

One prohibited app process may arrange only its own unique SwiftUI notes control's internal firstResponder and full UTF-16 selection. It may post at most one Unicode down/up pair to getpid only, with read-only posting preflight granted. The original NSWorkspace foreground PID must be positive, different from the fixture, and unchanged at every stage. Do not inspect any other application's AX tree or field/focus contents. Report before/after owner and event attempts. Normal NSApplication dispatch is used: if a non-key window does not receive input, record the hold instead of makeKey, custom dispatch/redirecting events, activation or global posting. Model success requires the actual SwiftUI Binding setter wrote the private model store, complete expected text equals that store and a fresh decoded readback. The self-owned proof neither verifies Apple behavior nor relaxes its foreground owner/focus gate.

## Unavailable context classification

The saved real foreground focus result `outputs/apw-apple-notes-focus-ready-live-20261012.json` returned `maintenance_locked` with stage `foreground_owner`, zero focus attempts and zero input. Static control flow shows that beginForegroundNotesProbeLease retained its stage, and later freshRoot/ready classified context absence as locked from a substring anywhere in values(ns). `unlocked`, ordinary notes mentioning `unlock`/`Touch ID`/`解锁`, or a row named Locked can all satisfy that classification. The saved report has no bound lock-screen controls, so it cannot establish actual macOS locking. This work does not infer that authentication is available or bypass any ready/lease/read guard.

Before classifying an unavailable context, required AX discovery must be complete. Incomplete discovery remains incomplete_window_observation; structural editable Title/User/Password/Notes fields remain user_editor_open. Otherwise context absence reports unavailable, with no assertion of lock merely from arbitrary text. No actual lock screen shape has been independently documented in this phase, so the helper does not claim a positive locked diagnosis. All paths remain fail closed. Native unavailable-context-policy entry must prove these cases without AppKit/Apple inspection.

## Repeatable isolated commands

These policy commands run the native `--policy-test` entry before AppKit initializes or any Apple process is inspected. Set HELPER to a locally compiled native helper and REPORT_DIR to a local output directory; report artifacts and binaries are not source files to commit.

```sh
swiftc native/maintenance.swift -o "$REPORT_DIR/apw-maintenance"
python3 tests/e2e_native_synthetic_input_policy.py --helper "$REPORT_DIR/apw-maintenance" --report "$REPORT_DIR/synthetic-input-policy.json"
python3 tests/e2e_native_context_classification.py --helper "$REPORT_DIR/apw-maintenance" --report "$REPORT_DIR/context-classification.json"
python3 tests/e2e_native_policy.py --helper "$REPORT_DIR/apw-maintenance" --report "$REPORT_DIR/native-regression.json"
```

The separate self-owned SwiftUI fixture is opt-in and is never run by default build verification. It compiles its own source in an ephemeral private directory, targets only its own PID, preserves the original foreground and requires existing event posting access. It must never be substituted with Apple Passwords or used as Apple acceptance evidence.

```sh
python3 tests/e2e_self_owned_notes_input.py --source native/test-fixtures/ForegroundNotesInput.swift --allow-own-pid-input --report "$REPORT_DIR/self-owned-input.json"
```

Each report stores the exact rerun command, helper or source hash, checks and a bounded result. The actual self-owned fixture proved one Binding model update and fresh persisted readback without a key window or app activation. This does not establish that Apple accepts the NotesField focus/selection/event/save sequence; that separate full-state test remains unverified.

## Post-input partial read boundary

A successful semantic Save and list return do not erase attempted-event provenance. The following independent persisted read can itself open an editor and then fail to return a complete NativeRead. The existing probe recovery policy formerly allowed two expected-postimage frames followed by Cancel in that error path. Its recovery failure could then clear ownEditor and report only the older probe review flag. This was a stricter-contract gap even though the recovery still required two complete unchanged states.

After any synthetic input attempt, a partial or failed owned read must return requires_review; it must not run recoverReadonlyEditor or clear ownership. A complete successful read still registers ownership before snapshot so final full persisted comparison and normal final Cancel can finish the operation. Error handling must set synthetic_input_editor_requires_review even if Save already cleared ownership and failure happens while rebuilding the exact query/index, before a new editor has been registered. EOF cleanup must observe the same attempted flag and cannot introduce recovery or implicit Cancel. Pre-input readonly recovery behavior remains unchanged. tests/e2e_native_synthetic_read_failure.py exercises this contract through the native early policy entry without Apple, events or authentication.
